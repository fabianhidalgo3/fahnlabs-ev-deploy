# API

Three HTTP APIs, all under `/api/v1`, JSON bodies, errors as RFC 9457 problem details
(`application/problem+json` with `title`, `status`, `detail`; validation errors add `fields`).
Times are epoch milliseconds.

- **BFF** (`http://<host>:9000/api/v1`): the API of the dashboard. Validates input and delegates to the motor.
- **Motor** (`http://<host>:9200/api/v1`): the domain API. Consumed by the BFF (optional header `X-Motor-Token`).
- **OCPP gateway** (`http://<host>:9100/api/v1`): OCPP command API and event stream, consumed by the motor
  (optional header `X-Gateway-Token`). Documented in [ocpp-gateway.md](ocpp-gateway.md).

## OpenAPI / Swagger

| Service | OpenAPI 3.1 spec | Swagger UI |
|---|---|---|
| BFF | `http://localhost:9000/v3/api-docs` (generated by springdoc from the controllers) | `http://localhost:9000/swagger-ui.html` |
| Motor | `http://localhost:9200/api/v1/openapi.yaml` ([source](../motor/internal/api/openapi.yaml)) | `http://localhost:9200/api/v1/docs` |
| OCPP gateway | `http://localhost:9100/api/v1/openapi.yaml` ([source](../ocpp-gateway/internal/gateway/openapi.yaml)) | `http://localhost:9100/api/v1/docs` |

The motor and gateway specs are written by hand and embedded in the binaries: update them when a route changes.
The WebSockets (`/ws/live`, `/api/v1/events`, `/api/v1/stream`) are described in this file and in
[ocpp-gateway.md](ocpp-gateway.md), not in OpenAPI.

## BFF

### State and configuration

| Method | Path | Description |
|---|---|---|
| GET | `/info` | Motor link status, public OCPP URL and gateway URL, emulator URL, whether the assistant has a key. |
| GET | `/state` | Live snapshot of the yard (latest one pushed by the motor). |
| GET, PUT | `/config` | Engine configuration; PUT is a partial update (`siteLimitKw`, `buildingLoadKw`, `buildingLoadMode`, `strategy`, `minPowerKw`, `safetyMarginKw`, `chargingRateUnit`, `voltage`, `phases`, `acceptUnknownChargers`, `energy{…}`). |

### Vehicles and chargers

| Method | Path | Description |
|---|---|---|
| GET, POST | `/vehicles` | List / create. Body: `name` (required), `make`, `model`, `vin` (17, no I/O/Q), `evccid` (MAC), `id_tag`, `battery_kwh`, `max_ac_kw`, `phases`, `target_soc`, `priority`. |
| GET, PUT, DELETE | `/vehicles/{id}` | Read / update / delete (204). |
| GET, POST | `/chargers` | Registry / pre-register (`id`, `location`, `maxPowerKw`, `priority`). |
| PUT, DELETE | `/chargers/{id}` | Update location, maximum power, priority / remove a disconnected charger (204). |
| POST | `/chargers/{id}/remote-start` | `{connectorId, idTag?, vehicleId?}` → charger answer `{status}`. |
| POST | `/chargers/{id}/remote-stop` | `{connectorId}` |
| POST | `/chargers/{id}/reset` | `{type: "Soft" \| "Hard"}` |
| POST | `/chargers/{id}/ocpp/{action}` | Any OCPP 1.6 CSMS command (`GetConfiguration`, `ChangeAvailability`, `UnlockConnector`, `TriggerMessage`…). Body: the OCPP payload; answer: the charger's CALLRESULT payload. Errors: `400` unknown command, `409` charger not connected, `502` CALLERROR (`ocppErrorCode`), `503` gateway down, `504` no answer. |

### Charging plans and sessions

| Method | Path | Description |
|---|---|---|
| GET, POST | `/charging-plans` | List (`from`, `to`) / create `{chargerId, connectorId, vehicleId?, idTag?, startAt?, departureAt?, targetSoc?, maxKw?}` (201). Without `startAt` it starts now. |
| DELETE | `/charging-plans/{id}` | Cancel (204). A running session goes on without the plan. |
| GET | `/sessions?from=&to=` | Sessions overlapping the range; running ones carry live values and `live: true`. |
| GET | `/sessions/{transactionId}/samples` | Power samples of a session. |

### Logs, energy and maintenance

| Method | Path | Description |
|---|---|---|
| GET | `/logs/ocpp` | OCPP frames. Filters: `chargerId` (`%` wildcard), `action`, `direction` (in/out), `kind`, `errorsOnly`, `text`, `from`, `to`, `limit`, `order`. |
| GET | `/logs/commands` | Commands sent to chargers joined with their answer and latency. |
| GET | `/logs/command-stats` | Per command: sent, rejected, no answer, mean latency. |
| GET | `/logs/summary` | Per charger, per action, most frequent errors. |
| GET | `/logs/events`, `/logs/actions` | Engine events; OCPP actions seen in the last 7 days. |
| GET | `/energy/report?from=&to=&groups=` | Energy indicators (see [energy-management.md](energy-management.md)). |
| GET | `/energy/groups` | Yards (charger ID prefixes) with sessions, and the current tariffs. |
| GET | `/maintenance/health?chargerId=&days=` | Health and risk per charger. |
| GET | `/maintenance/history?chargerId=&days=&bucket=day\|hour` | Time series of one charger. |
| GET | `/maintenance/forecast?chargerId=&horizonDays=&windowDays=` | Failure forecast. |

### Exports, assistant, live

| Method | Path | Description |
|---|---|---|
| GET | `/exports/{sessions\|meter-samples\|site-samples\|vehicles\|chargers}.csv` | CSV, UTF-8 with BOM (`meter-samples.csv?transactionId=`, `site-samples.csv?from=`). |
| GET | `/assistant/status` | `{configured}` |
| POST | `/assistant/messages` | `{messages: [{role, content}], language: "en" \| "es"}` → `{reply, steps, usage, stop, navigate?}` |
| WS | `/ws/live` | `{"type":"snapshot","data":{…}}` about twice per second; `{"type":"motor","data":{"connected":bool}}` on link changes. |
| GET | `/actuator/health` | Service health. |

## Motor

Same resources as the BFF with these differences:

| Path | Notes |
|---|---|
| `/state`, `/config`, `/vehicles`, `/chargers`, `/charging-plans`, `/sessions`, `/logs/*`, `/energy/*`, `/maintenance/*` | As above. |
| `GET /sessions/active` | Sessions in memory with live values. |
| `GET /exports/{sessions\|meter-samples\|site-samples\|vehicles\|chargers}` | JSON rows (the BFF builds the CSV). |
| `POST /queries/sql` | `{sql}` — one read-only SELECT on PostgreSQL, 5 s, 200 rows. |
| `POST /queries/mongo` | `{collection, pipeline}` — aggregation with allowed stages only, 5 s, 200 rows. |
| `GET /health` | `{status, service, connectedChargers}` |
| `WS /api/v1/events` | Live snapshots. |
| `GET /vehicles` | Also allowed cross-origin (CORS), for the web emulator served by the gateway. |

The OCPP endpoint for chargers (`ws://<host>:9100/ocpp/{chargePointId}`) and the web emulator (`/emulator/`) belong
to the gateway, not to the motor.
